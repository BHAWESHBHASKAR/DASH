## Method and limits

- An issue is **CLOSED** only when the fix is present in the code on this commit (file:line) and at least one named test exercises the fixed behavior and passed in a run recorded here. Per-test results were read from the log of the `cargo test --workspace --exclude dash-e2e` run, the log of the `cargo test -p dash-e2e` run, and the SDK runs listed below (Java `mvn`, C# `dotnet test`, Kotlin `gradle test`). Black-box (e2e) tests are listed first where one exists. **PARTIAL** means the fix exists but a test is missing, cannot fail on the old behavior, or part of the fix is missing. **OPEN** means no fix. **N/A-SUPERSEDED** was not needed.
- Whether a test would fail on the old code was judged by reading the test and the fix; the old code was not rebuilt and re-run for each issue.
- Deploy and documentation items are verified by reading the files and by the validators that could run here (they are named in the Notes column). Their CLOSED status rests on that reading plus the validator result, not on a failing-then-passing test.
- Issues whose Phase column has no `P0` are listed as `open (phase X)` unless they were fixed ahead of their phase. For those, the status is **closed early**, judged by the same standard (fix at file:line, named tests that passed in the runs above); the Notes column says what was and was not covered. Rows with partial early work stay `open (phase X)` and say what is left.
- Scope note: where the Phase column is split (for example `P0 / P2`), the status refers to the P0 part; the later part is named in Notes.
- Tests with a timing race were re-run: see ROB-04 (per-IP connection cap tests).

## Behavior changes operators must know

Each item is taken from the code or its tests on this commit; the source is given in parentheses.

- **Authentication is deny-by-default.** A service with no API key, scoped key, JWT secret or OIDC config rejects every non-probe request and refuses to start. `DASH_INSECURE_DEV_MODE=1` re-opens it and forces a loopback bind unless `DASH_INSECURE_DEV_MODE_ALLOW_NON_LOOPBACK` is set. A blank `DASH_*_ALLOWED_TENANTS` is a startup error, not "any tenant". A request carrying two `Authorization` or two `x-api-key` headers is rejected with 400 (services/common/src/policy.rs, services/common/src/lib.rs:218, services/retrieval/src/transport/http.rs:186).
- **Strict secrets are on by default.** `DASH_STRICT_SECRETS` defaults on (off only with dev mode). API keys, replication tokens and the control-plane token need at least 16 characters, HS256 JWT secrets at least 32. Placeholder values (`change-me`, `replace-me`, `example`, `<...>`, values starting `secret`/`password`) are rejected, and the error text does not echo the value (services/common/src/lib.rs:103, services/common/src/lib.rs:109, services/control-plane/src/lib.rs:107).
- **Environment variable names.** Ingestion reads `DASH_INGEST_*` (not `DASH_INGESTION_*`). Ollama is configured with `DASH_OLLAMA_ENDPOINT`; `DASH_OLLAMA_BASE_URL` is a deprecated alias and a base URL without a path is expanded to `/api/embed` (pkg/embeddings/src/lib.rs:318). `DASH_LOG_LEVEL`, `DASH_*_TRANSPORT_RUNTIME` and `DASH_*_JWT_PUBLIC_KEY` are not read (docs-site/docs/reference/configuration.md). `scripts/check_deploy_env.sh` and `scripts/check_config_docs.sh` check names against the code.
- **New required secrets and settings.** Compose requires the secrets for ingestion (API key, HS256 secret, replication token), retrieval (API key, HS256 secret, replication token) and the control plane (token), and refuses to start without them (deploy/container/docker-compose.yml:75). Generate them with `scripts/generate-secrets.sh` (mode 0600). The control plane needs `DASH_CONTROL_PLANE_TOKEN` and refuses to start without it outside dev mode; **`DASH_CONTROL_PLANE_NODE_ID` is now required outside dev mode** (a unique, stable id per node; the old `control-plane-<pid>` default is gone) (services/control-plane/src/lib.rs:188); the metadata-router client sends `DASH_ROUTER_CONTROL_PLANE_TOKEN`.
- **Native TLS (opt-in).** `DASH_{INGEST,RETRIEVAL,CONTROL_PLANE}_TLS_CERT_FILE` and `_KEY_FILE` switch a listener to HTTPS only (plaintext requests get 400); `_TLS_CLIENT_CA_FILE` verifies client certificates and `_TLS_REQUIRE_CLIENT_CERT` makes them mandatory (probes included). The handshake must finish within `DASH_HTTP_FIRST_BYTE_TIMEOUT_MS`. Followers use `https://` sources with `DASH_REPLICATION_CA_FILE` and `DASH_REPLICATION_CLIENT_CERT_FILE` / `_KEY_FILE`; ingestion can require a follower certificate on the replication routes (`DASH_INGEST_REPLICATION_REQUIRE_CLIENT_CERT`, `DASH_INGEST_REPLICATION_ALLOWED_CLIENT_CERTS`). A half-set TLS configuration refuses to start. Certificates reload on content change (docs/operations/tls.md).
- **Replication endpoints are closed by default.** `/internal/replication/*` on ingestion answers only when `DASH_INGEST_REPLICATION_TOKEN` is set and sent as `x-replication-token` (constant-time compare). With no token they stay closed; dev mode opens them only when no authentication is configured at all (services/ingestion/src/transport/replication.rs:479). Followers can use `https://` sources (and refuse to send the token over plain `http://` to a non-loopback host unless `DASH_REPLICATION_ALLOW_INSECURE_HTTP=1`), but the ingestion listener itself still speaks plain HTTP; see docs/operations/replication-security.md.
- **Rate limiting is enforced.** A token bucket applies to API-key, JWT and OIDC requests and returns 429 with `Retry-After`. Buckets are keyed by route class, a keyed hash of the credential and, for tenant-bound credentials, the tenant (a wildcard key cannot gain capacity by rotating tenant ids); the bucket table is capped and evicts the oldest entry. Defaults: retrieval 500 rps burst 1000; ingestion 100 rps burst 200 (`DASH_*_RATE_LIMIT_PER_TENANT_RPS`, `DASH_*_RATE_LIMIT_BURST`).
- **Roles, tokens and OIDC.** **A JWT without a role claim gets no roles and is answered 403 on every role-checked route** unless `DASH_*_JWT_DEFAULT_ROLES` is set; unscoped legacy API keys get `DASH_*_API_KEY_DEFAULT_ROLES` (default: the service's primary role); `admin` implies the other roles. `exp` is required, lifetime is capped (default 86400 s, `DASH_*_JWT_MAX_LIFETIME_SECS`), leeway is capped at 60 s, a `*` tenant claim is ignored unless `DASH_*_JWT_ALLOW_WILDCARD_TENANT` is set, and OIDC needs `aud`, `iss` and an https JWKS URL (loopback or `DASH_OIDC_ALLOW_INSECURE_JWKS=1` excepted); incomplete OIDC config is a startup error. Revoked `jti` values are denied (`DASH_*_JWT_REVOKED_JTIS[_PATH]`). The policy is built once at start and reloaded on SIGHUP.
- **Operations and previously open routes need credentials.** `/v1/embeddings` needs the `retrieve` role. **`/metrics` and `/debug/*` need the `admin` role or an unscoped key; a tenant-scoped key or a JWT without `admin` gets 403** (`DASH_METRICS_PUBLIC=1` makes `/metrics` public). Health, live and ready probes stay open. Authorization happens before any embedding-provider call (services/common/src/policy.rs:464, services/retrieval/src/transport.rs:1496).
- **Control-plane authentication-failure throttle.** After 10 failed bearer-token attempts from one peer address within 60 seconds, that peer gets 429 with `Retry-After` until the window ends (tracked peers capped at 10000); successful requests and open routes do not count (services/control-plane/src/lib.rs:201).
- **Identifier length limit.** Tenant, claim, document and commit identifiers longer than 256 bytes are rejected with 400 before authentication, so anonymous callers cannot push large values into audit records or logs (services/ingestion/src/transport/ingest_routes.rs:934, services/retrieval/src/transport/payload.rs:6). Control characters in identifiers are rejected at validation as before (pkg/schema/src/lib.rs:188).
- **HTTP limits and connection handling.** Header line over 8 KiB, header block over 32 KiB, or more than 100 headers returns 431; `Transfer-Encoding: chunked` returns 501; conflicting duplicate `Content-Length` returns 400; body over 16 MiB returns 413; JSON nesting beyond 64 and duplicate JSON keys return 400; a query string with invalid percent-encoding returns 400 instead of dropping the parameter; whitespace before a header colon, obsolete line folding and malformed HTTP versions return 400, and HTTP/2.0 or HTTP/0.9 request lines return 505; `Expect: 100-continue` returns 417. The whole request must arrive within `DASH_HTTP_REQUEST_TIMEOUT_MS` (default 10000), measured from accept, or the connection is dropped with 408. **A socket that sends nothing is closed after the first-byte timeout, `DASH_HTTP_FIRST_BYTE_TIMEOUT_MS` (default 2000), without taking a worker. Each client IP may hold at most `DASH_HTTP_MAX_CONNS_PER_IP` connections (default 64, 0 disables); extra connections get 503.** `/health`, `/live`, `/ready` and `/metrics` are served on a reserved lane so slow embedding calls cannot starve probes. Accept errors no longer stop the server (services/common/src/conn.rs:23, services/common/src/conn.rs:21).
- **Embedding concurrency cap and breaker.** **Embedding provider calls are capped at `DASH_EMBEDDING_MAX_CONCURRENCY` (default 8, 0 = unlimited); a request that cannot get a slot within `DASH_EMBEDDING_QUEUE_WAIT_MS` (default 250) gets 503 with `Retry-After`.** A circuit breaker (`DASH_EMBEDDING_BREAKER_THRESHOLD` default 5, 0 = off; `DASH_EMBEDDING_BREAKER_RESET_MS` default 10000) opens on repeated server-side failures, admits a single probe when half-open, and ignores client errors. Provider outages return 503 (with `Retry-After`), malformed or non-finite provider output returns 502, and error bodies carry short codes without internal detail (pkg/embeddings/src/lib.rs:902, pkg/embeddings/src/lib.rs:1061).
- **Embeddings routes and providers.** Credentials over plain `http://` are refused for non-loopback hosts unless `DASH_EMBEDDING_ALLOW_INSECURE_HTTP=1`; the client is TLS-capable, bounds bodies, does not follow redirects and retries within a deadline. Token-array input to `/v1/embeddings` is rejected unless enabled; empty strings, too many inputs, oversized totals and a provider count mismatch return 400 or 502 with short codes (pkg/embeddings/src/http.rs:99, services/retrieval/src/openai_embeddings.rs).
- **Evidence and edges are upserts.** Evidence is keyed by `evidence_id` and edges by (from, to, relation); re-ingesting replaces rather than appends, and graph traversal collapses edges that share an edge id but differ in target or relation. Citation counts that were inflated by earlier restarts drop after a rebuild from the WAL (pkg/store/src/lib.rs:2866, pkg/store/src/lib.rs:2884).
- **Batch ids and idempotency.** A known `commit_id` with unchanged content is an idempotent replay; the same `commit_id` with changed content is an update, reported with `updated: true`, instead of being dropped. Document and claim ids are derived without tenant/document collisions, so ids generated for the same input differ from those of older versions (services/ingestion/src/transport.rs:531, services/ingestion/src/extraction.rs:823).
- **Ingest validation.** An edge whose target claim belongs to another tenant is rejected on write with a conflict error; an all-zero claim embedding is rejected; non-finite vectors are rejected (services/ingestion/src/transport/tests.rs:2132).
- **WAL format and recovery.** New WAL records are versioned and checksummed. A torn final record is truncated at open, and the removed bytes are saved to a `<wal>.truncated-<unix-ms>` sidecar. **Corruption in the interior of the WAL, including a damaged group marker, is a hard error that names the line; nothing is truncated.** Pre-checksum records are still read. By default unreadable legacy records are quarantined to a side file and replay continues; set `DASH_WAL_REPLAY_STRICT=1` to fail instead. Packed-list lengths are checked (a huge length is an error, not a panic). A `<wal>.generation` file identifies the WAL lineage and changes at every checkpoint/compaction. Use `tools/wal-inspect` (`inspect`, `verify`, `repair`) before manual surgery (pkg/store/src/wal.rs:839, pkg/store/src/wal.rs:1500, pkg/store/src/wal.rs:92).
- **Replication protocol.** Frames carry the WAL generation. Followers persist (generation, offset) and resync from a snapshot after leader compaction or an unknown generation, replacing their state instead of merging; the ingestion follower checks its cursor against its own WAL and resyncs fully if the WAL was truncated. Delta frames never split a commit group, and a group larger than the cap is an explicit counted error. The leader skips lines that a lenient replay would quarantine and followers apply leniently; unfixable failures show up as a blocked reason in `/ready` and in metrics. A panic during apply is caught and does not poison the runtime. Followers ack batch commits from v2 WAL lines. Retrieval readiness reports follower lag and a dead leader (`DASH_*_REPLICATION_MAX_STALENESS_MS`). An old offset-only state file is accepted.
- **Atomic ingest.** A single ingest is written as one WAL commit group; an incomplete group is discarded on replay. If the checkpoint after a committed write fails, the response reports the checkpoint as deferred rather than returning an error.
- **Ranking.** Support and contradiction edges now count toward the target claim, not the author; dangling and cross-tenant edges are ignored; the support bonus and contradiction penalty saturate; repeated evidence from one source counts once. Result scores and order change relative to earlier versions (pkg/ranking/src/lib.rs:82).
- **Cross-tenant errors.** A claim-id conflict with another tenant returns a generic 409 that does not name the other tenant (the 409 still reveals that the id exists: SEC-18, P2). Vector and lexical fallbacks no longer search other tenants.
- **Segment directories moved; migration needs a marker.** Per-tenant segment directories use an injective name. **A legacy directory is adopted only when its `segments.tenant` marker names the requesting tenant; directories written by older versions have no marker, are left untouched with a warning, and the segments are rebuilt under the new name.** Segment files are never overwritten in place, and unreferenced files are pruned only after a grace period (services/indexer/src/lib.rs:198, services/indexer/src/lib.rs:113).
- **Placement and control plane.** Ingestion stops accepting writes once the placement source has been failing longer than `DASH_INGEST_PLACEMENT_STALE_GRACE_MS` (default 30000), and epoch regressions are rejected. The metadata-router client no longer falls back to a stale placement file unless `DASH_ROUTER_ALLOW_STALE_PLACEMENT` is set. Control-plane promotion refuses an unknown or lagging replica unless forced. The lease is durable, cross-process locked, uses a monotonic clock, carries a fencing token and keeps an epoch floor sidecar so epochs never restart; lease files are created owner-only (0600, directories 0700) and symlinks are refused; an implausible lease record is reported as an error, and `DASH_CONTROL_PLANE_LEASE_RESET=1` is the administrator recovery (services/control-plane/src/leader.rs:703, services/control-plane/src/main.rs:128).
- **Audit log.** Ingestion and retrieval write one canonical record format that the shared verifier (`tools/audit-verify`, `scripts/verify_audit_chain.sh`) accepts; legacy lines still verify; a torn tail is truncated and writes are file-locked. The actor is the credential the policy actually evaluated (kind api_key, jwt or oidc, with a 16-hex HMAC fingerprint, never the secret; set `DASH_AUDIT_FINGERPRINT_KEY` so fingerprints correlate across restarts and replicas, otherwise a random per-process key is used and a warning is logged). Request fields are bounded, denial records are throttled and counted, and the audit file is created owner-only. Audit remains off unless `DASH_INGEST_AUDIT_LOG_PATH` / `DASH_RETRIEVAL_AUDIT_LOG_PATH` is set; compose, k8s, Helm and systemd examples set them. `DASH_*_AUDIT_FAIL_CLOSED=1` makes a failing audit log refuse ingest and retrieve (503); the default only logs and counts failures. The chain is still unkeyed (SEC-17, P4).
- **Deployment artifacts.** Compose ports bind 127.0.0.1, containers run read-only with all capabilities dropped, and binaries are root-owned. **Compose uses one named volume per service** (`dash-ingestion-state`, `dash-retrieval-state`, `dash-control-plane-state`; segment-maintenance shares the ingestion volume), so an existing deployment with a shared volume must move its data (deploy/container/docker-compose.yml:63). Kubernetes/Helm no longer mount an `emptyDir` over `/opt/dash`, wire retrieval to ingestion for replication, route `/v1/ingest*` to ingestion, probe `/v1/ready`, and no longer ship HPAs or default secrets (Helm refuses to render without secrets, or with placeholders). Images are named `ghcr.io/<owner>/dash-<service>`. systemd units use per-service state directories.
- **SDKs.** Java, Kotlin and C# no longer expose `delete`; ingest is marked experimental, goes to a separate ingestion URL, and is not retried unless an idempotency key is set (the server ignores that header); the retrieve default omits `top_k` so the server default (5) applies; the C# retrieve model reads `results` with a numeric score. The Go, Python and TypeScript SDKs decode `encoding_format: base64` embeddings and accept a `dimensions` request parameter; live-integration tests are opt-in (`DASH_LIVE_URL`). SDK version is 0.2.0 across languages.
