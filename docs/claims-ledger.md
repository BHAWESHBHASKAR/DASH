# Claims Ledger

Every capability claim made in [`README.md`](../README.md) is listed here with a status and the evidence that proves it. This implements rule 3 of section 9.2 of the [production-readiness master plan](plans/2026-10-09-production-readiness-master-plan.md): docs may not claim what the ledger cannot prove.

**Status values**

- `verified`: a test named in the Proof column exercises the claim, and the test exists in the repository. (Whether it passed is the CI result; the checker below only proves the reference is real.)
- `partial`: the claim holds with a known defect or only part of it is tested; the Notes column says which part.
- `planned`: the claim describes behavior that does not exist yet (the README labels it v0.3.0 or planned); there must be no test for it today.

**Proof column syntax** (machine-checked by [`scripts/check_claims_ledger.sh`](../scripts/check_claims_ledger.sh)):

- `` `path/to/file.rs::test_name` `` names a test: the file must exist and contain the function (`fn name` for Rust, `def name` for Python, `func name` for Go, the literal name for other languages).
- `` `doc:path/to/file` `` names a file or document that must exist (an anchor after `#` is ignored).
- A `verified` row must contain at least one test reference, except rows that state a static repository fact (the license, the crate list, the count table), which may cite `doc:` paths alone. A `planned` row must not cite a test as proof.

Run `scripts/check_claims_ledger.sh` before changing the README. It also fails if the Rust test count printed in the README no longer matches the repository (set `CLAIMS_LEDGER_SKIP_COUNTS=1` to skip that check).
