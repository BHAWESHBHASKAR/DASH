# Benchmark and drill history

The files in this directory are **outputs of local benchmark runs and operational drills**, committed over time. They are not a published performance claim, and nothing in the README or the docs site cites them as one.

## What is here

| Path | What it is |
|---|---|
| `benchmark-history.csv`, `benchmark-history.md` | Rows appended by the benchmark harness (`tests/benchmarks`, via `scripts/ci.sh`). `scripts/ci.sh` passes `benchmark-history.md` to `--guard-history` as the baseline for its regression guard, so this file is an input to a script, not only a record. At the time of writing it holds a single `smoke` row from a local run (epoch `1771399725`). |
| `rebalance/` | Before/after placement and debug snapshots from the rebalance drills (`scripts/rebalance_drill.sh`, phase 4 scale-proof scripts). |
| `recovery/` | Output of the recovery drill (`scripts/recovery_drill.sh`). |
| `incidents/` | Incident-simulation gate output (`scripts/incident_simulation_gate.sh`) with a `.sha256` file. |

Other history directories that the scripts write to (`runs/`, `concurrency/`, `docs/benchmarks/scorecards/`) are git-ignored.

## How to read these files

- They come from smoke-sized fixtures on whatever machine ran them (the hardware is not recorded in the files). Latencies and counts are not comparable across rows and say nothing about production performance.
- No cross-system comparison (against Pinecone, Qdrant, Milvus, Weaviate or Chroma) exists in this repository. Do not infer one from these numbers.
- Where an earlier document quoted a figure from here without a reproducible command and environment, treat that figure as unverified.
- A guard threshold passing in `scripts/ci.sh` means the current run was not worse than the recorded baseline in this directory, which is itself an unversioned local measurement.

## Plan

Per the master plan (section 9, truth-keeping, and the benchmark/evaluation work in P5 and P7), run outputs are to move out of the repository:

1. CI uploads benchmark and drill outputs as workflow artifacts (with the commit SHA, runner type and command recorded alongside the data).
2. A small, curated baseline file used by the regression guard stays in the repository, regenerated by CI rather than by hand.
3. The existing files here are **not deleted in this pass**; they are removed once CI artifacts and the curated baseline exist, so that `scripts/ci.sh` keeps working in the meantime.

Until then, any benchmark number in documentation must cite a command, a commit and a machine description, or be labeled unverified.
