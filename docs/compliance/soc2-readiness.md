# SOC 2 Readiness Mapping: DASH

> **Status (0.3.0 unreleased tree): this is a readiness plan, not an attestation.** DASH has not been audited, has no SOC 2 report, and several controls below are partial or not implemented. The "Current status" column states what the code and CI show; where a control was only planned in the 2026-10-09 review and the code has since merged, it is marked implemented with the test or file that evidences it (register item DOC-06). Remediation of what remains is tracked in the [master plan](../plans/2026-10-09-production-readiness-master-plan.md), the [issue register](../plans/2026-10-09-issue-register.md) and the [P0 status register](../plans/2026-10-09-p0-status.md). Status words: **implemented**, **partial** (works with a known gap), **library only** (code exists, not used), **NOT IMPLEMENTED**, **planned (phase)**.

This document maps DASH controls to the AICPA Trust Services Criteria for **Security** and **Availability** for a self-hosted vector database.

## Scope

- **System**: DASH ingestion, retrieval, control-plane, indexer and metadata-router components.
- **Environment**: self-hosted deployments via Docker Compose, Helm, Kubernetes manifests or systemd.
- **Readiness target**: three months of evidence collection before an audit, after the remaining phases close the gaps below.

## Evidence collection

`scripts/soc2_evidence_collector.sh <output-dir>` gathers repository metadata, CI workflow definitions (not run logs), the result of `scripts/ci.sh`, backup/restore drill logs when available, Prometheus rule files, whether encryption at rest is configured (never the key), and `cargo audit` output when available. It is a convenience for assembling evidence; it does not make a control operate. No collected evidence set exists in this repository.

## Known gaps and next steps

1. **Remaining P0 verification:** see the [P0 status register](../plans/2026-10-09-p0-status.md).
2. **P1:** key lifecycle (expiry, review metadata, hashed storage); more OIDC coverage (other algorithms, a real IdP); fuzzing of parsers and authz; TLS on by default in the shipped deployment artifacts.
3. **P3:** consensus replication and automatic failover.
4. **P4:** cloud KMS key providers and per-tenant data keys (crypto-shredding) on top of the file encryption that now exists; keyed audit chain with anchoring and retention.
5. **P7:** signed images, provenance, digest pinning, external penetration test.

The AWS KMS provider and external uptime probe mentioned in earlier versions are not implemented and are not currently scheduled in a specific phase.

## Roles and responsibilities

- **Engineering**: maintain controls, fix findings, and keep evidence current.
- **Security/Compliance**: review collector output, track exceptions, and coordinate auditor access.
- **Operations**: run backups, monitor alerts, and own incident response playbooks.

The policy templates in [`policies/`](policies/) state target policy; each carries a status note.
